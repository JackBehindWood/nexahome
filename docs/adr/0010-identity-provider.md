# 0010. Identity provider: Pocket ID

* **Status:** Proposed
* **Date:** 2026-10-22

## Context
P2.5 wants one login for NexaHome apps, two roles (`admin`, `users`) and a reserved `agents` group that is never admin and has no client access. Requirements R1 to R10 are in the P2.5 plan. Apps stay replaceable clients: they rely only on an OIDC discovery URL, a client id and secret, and a `groups` claim (R9). Spike on 2026-10-21 and 2026-10-22 (macOS, Colima 2 CPU / 2 GB, Safari; the throwaway project and its volumes are removed). Related: [ADR 0007](0007-stack-contract.md), [ADR 0008](0008-backup-tool.md), [ADR 0011](0011-edge-and-local-hostnames.md).

## Decision (Proposed)
Use Pocket ID as `stacks/identity`: passkey-only logins, OIDC, groups restrict access per client, SQLite. Pin `ghcr.io/pocket-id/pocket-id:v2.18.0-distroless`. Not v2.19.0: it was released hours before the spike. Authelia stays the fallback (not measured).

Interface a client must provide: discovery URL `http://id.${NEXAHOME_DOMAIN}:${EDGE_PORT}/.well-known/openid-configuration`, client id, client secret, callback `<app>/openid/callback`. The issuer carries the edge port, so it changes with the hostname or port ([ADR 0011](0011-edge-and-local-hostnames.md)).

| Item | Measured |
| :-- | :-- |
| Image | arm64 manifest present; 110 MB; BSD-2-Clause; user 65532 built in; own `healthcheck` subcommand (90 s interval) |
| Hardening | runs with `read_only`, `cap_drop: ALL`, `no-new-privileges`, no published port |
| Idle RAM | 17 MiB (two readings, the second after a restart) |
| Data path | The image has no `/app/data`, so a new volume there is root-owned and a non-root start fails ("unable to open database file"). Works: mount the volume at the image's built-in non-root home directory (exists, owned by 65532, copied into a new volume) and point `DB_CONNECTION_STRING`, `UPLOAD_PATH`, `GEOLITE_DB_PATH` into it. Restore through `make restore` not tested |
| Outbound | `ANALYTICS_DISABLED` and `VERSION_CHECK_DISABLED` set: no outside connection seen (established sockets, log scan). Internal UDP 1414 (task runtime), not published |
| Recovery | `docker exec <container> /app/pocket-id one-time-access-token <user>` works without a shell; prints a one-hour sign-in link (used) |
| Seeding | `STATIC_API_KEY` (admin-level) created groups, users, client `actual` with a chosen id, and a client secret (`POST /api/oidc/clients/<id>/secrets`, several allowed, so rotation works). The secret is generated by the provider and returned once, so a client's `.env` cannot be a pure Git file |
| Group rule | A client needs `isGroupRestricted: true`. With only the allowed-groups list set, a user in no group was authorised (audit log). After the flag: `access_denied`, "You are not allowed to access this service" (agentx in `agents`; mallory) |
| Passkey | Registered and signed in on `http://id.*.localhost:<port>` in Safari (reported by the owner). Chrome and Firefox not installed here, not tested |
| Actual | Login through the `http://` issuer works for the first user, who becomes server owner (callback logged). An unknown user is refused with 400 `openid-grant-failed`. Matching claim and the full path for a second allowed user: not tested |

## Failure modes
- Pocket ID exited once (code 1, "host is not registered" from its internal health check) about 35 minutes after start. Cause not established. Needs `restart: unless-stopped`; data was intact after the restart. While it was down, Actual's page was blank in the browser (likely, not proven).
- Provider down: new SSO logins fail, apps with a valid session and the Actual password fallback keep working (R5, to be verified in S3).
- Lost `ENCRYPTION_KEY`: a restored database is unusable; keep it with the restic password.

## Consequences
- **Owner feedback (2026-10-22):** the test flow (one-time links, private windows, passkey prompts, "Something went wrong" in Actual when refused) felt poor, and the owner wants one command-centre page to sign in to, usable by an admin and an agent. The daily path (one passkey sign-in, then tiles) was measured only for one user. Agents never use passkeys (R2), so an agent login to the page needs a separate mechanism. **Open:** gate the portal itself, or only the apps; owner to decide.
- Open for S2: create the client by hand in the UI or with a small script; remove or rotate `STATIC_API_KEY` after seeding.
- A second Actual user must be created in Actual first (default creation mode `manual`, per upstream docs; unknown user refusal measured).
- R6: identity adds 17 MiB (see ADR 0011 for the total).

## Alternatives
Authelia (file users and forward auth; fallback), Authentik, Keycloak, Zitadel (need Postgres; not measured), Kanidm (larger operating model), no provider in P2.5 (portal only; each app keeps its own login: the cheaper way back, cost is a login per app and no roles), a custom login (rejected: no custom login code).
